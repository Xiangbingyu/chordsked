## 1. 需求对照分析

### 1.1 与需求文档 `06-校区管理需求.md` 的对照

| 需求项 | 需求文档要求 | 本计划实现 | 差异说明 |
|--------|-------------|-----------|---------|
| 校区列表查询 | 分页、关键词搜索、状态筛选 | ✅ 完全实现 | 无差异 |
| 列表字段 | ID、名称、地址、电话、负责人、用户数量、状态、创建时间 | ⚠️ 部分调整 | 见下方说明 |
| 校区创建 | 名称唯一、地址、电话、负责人、备注 | ✅ 完全实现 | 新增 `code` 字段 |
| 校区编辑 | 修改名称、地址、电话、负责人、状态、备注 | ✅ 完全实现 | 无差异 |
| 校区删除 | 有用户关联时不可删除 | ✅ 完全实现 | 物理删除，检测教务+教师 |
| 数据权限 | 基于用户校区绑定过滤 | ✅ 完全实现 | 使用 `@DataScope` 注解 |
| 审计日志 | 创建、编辑、删除必须记录 | ✅ 完全实现 | 使用 `AuditLogRequestUtils` |

### 1.2 字段调整说明

**列表字段调整**：
- 需求文档要求显示"地址"，本计划列表中**不显示地址**（详情接口才返回）
- 需求文档要求显示"用户数量"，本计划**暂不显示**（后续如需可添加）
- 新增 `code`（校区编码）字段，用于后续排课和教室分配

**原因**：
- 地址字段较长，列表展示影响可读性，详情查看更合理
- 用户数量统计涉及三表关联（教务、教师、学员），性能开销较大
- `code` 字段为后续教室管理、排课功能预留

### 1.3 删除方式调整

| 对比项 | 需求文档 | 本计划 | 原因 |
|--------|---------|--------|------|
| 删除方式 | 未明确 | **物理删除** | 逻辑删除与停用功能重复 |
| 关联检测 | "有用户关联时不可删除" | 仅检测**教务账号**和**教师** | 学员与老师绑定而非校区 |

## 6. 业务规则

### 6.1 唯一性校验

**校区编码唯一性**:
- 创建时：检测 `code` 是否已存在
- 修改时：检测 `code` 是否与其他校区冲突（排除自身）

**校区名称唯一性**:
- 创建时：检测 `name` 是否已存在
- 修改时：检测 `name` 是否与其他校区冲突（排除自身）

### 6.2 数据权限过滤

**实现方式**:
- Mapper XML 中使用 `/*DATA_SCOPE*/` 占位符
- `@DataScope(tableAlias = "c", scopeField = "id")` 注解
- MyBatis 拦截器自动注入权限条件

**过滤规则**:
- 全公司权限：无过滤
- 指定校区权限：仅显示绑定的校区
- 本人权限：仅显示相关校区

### 6.3 删除前置检测

**检测逻辑**:
1. 检测 `sys_user_campus` 表中是否有教务账号绑定该校区
2. 检测 `sys_teacher_user` 表中是否有教师属于该校区
3. 任一检测有数据则拒绝删除

**错误提示**:
- 教务账号绑定：`"校区有教务账号绑定，请先移除用户"`
- 教师绑定：`"校区有教师绑定，请先移除教师"`

### 6.4 负责人同步

**修改时**:
- 如果传入 `leaderId`，自动从 `sys_internal_user` 表查询 `name` 字段
- 更新 `leader_name` 字段

**创建时**:
- 同修改逻辑

### 6.5 审计日志

**记录操作**:
- 创建校区
- 修改校区
- 删除校区

**记录内容**:
- 操作人 ID、姓名
- 操作类型（CREATE/UPDATE/DELETE）
- 校区 ID
- 请求参数摘要
- 响应结果摘要

### 6.6 状态校验

- 创建时：`status` 必须为 0 或 1
- 修改时：`status` 必须为 0 或 1
- 查询时：过滤 `status = 2`（已删除）的记录

## 9. 关键设计点

### 9.1 数据权限集成示例

**Mapper 注解**:
```java
@DataScope(tableAlias = "c", scopeField = "id")
List<CampusQueryResultVO> listByQuery(@Param("request") CampusQueryRequest request);
```

**Mapper XML**:
```xml
<select id="listByQuery" resultType="...">
    SELECT c.id, c.code, c.name, c.leader_name, c.phone, c.status, c.created_at
    FROM sys_campus c
    WHERE c.status != 2
    <if test="request.keyword != null and request.keyword != ''">
        AND (c.name LIKE CONCAT('%', #{request.keyword}, '%')
             OR c.code LIKE CONCAT('%', #{request.keyword}, '%'))
    </if>
    <if test="request.status != null">
        AND c.status = #{request.status}
    </if>
    /*DATA_SCOPE*/
    ORDER BY c.sort ASC, c.id ASC
    LIMIT #{request.pageSize} OFFSET #{request.offset}
</select>
```

### 9.2 删除检测示例

```java
@Transactional(rollbackFor = Exception.class)
public void delete(CampusDeleteRequest request) {
    // 1. 权限校验
    operationGuardService.validateOperation(request.getCampusId());
    
    // 2. 检测教务账号绑定
    int internalUserCount = userCampusDao.countByCampusId(request.getCampusId());
    if (internalUserCount > 0) {
        throw new BusinessException(ErrorCode.BAD_REQUEST, "校区有教务账号绑定，请先移除用户");
    }
    
    // 3. 检测教师绑定
    int teacherCount = teacherUserDao.countByCampusId(request.getCampusId());
    if (teacherCount > 0) {
        throw new BusinessException(ErrorCode.BAD_REQUEST, "校区有教师绑定，请先移除教师");
    }
    
    // 4. 物理删除
    int rows = campusDao.deleteById(request.getCampusId());
    if (rows == 0) {
        throw new BusinessException(ErrorCode.BAD_REQUEST, "校区不存在");
    }
    
    // 5. 记录审计日志
    auditLogService.record(...);
}
```

### 9.3 负责人同步示例

```java
@Transactional(rollbackFor = Exception.class)
public void update(CampusUpdateRequest request) {
    // 1. 权限校验
    operationGuardService.validateOperation(request.getCampusId());
    
    // 2. 唯一性校验
    writeValidator.validateForUpdate(request);
    
    // 3. 如果传入负责人 ID，自动查询姓名
    if (request.getLeaderId() != null) {
        InternalUserEntity leader = internalUserDao.getById(request.getLeaderId());
        if (leader == null) {
            throw new BusinessException(ErrorCode.BAD_REQUEST, "负责人不存在");
        }
        request.setLeaderName(leader.getName());
    }
    
    // 4. 更新校区
    campusDao.updateById(request);
    
    // 5. 记录审计日志
    auditLogService.record(...);
}
```

## 14. 注意事项

### 14.1 与现有模块的一致性
- 严格遵循项目命名规范（`@Resource(name = "...")`）
- Service 实现必须显式声明 `@Service("xxxService")`
- Controller 使用 `@Validated` + Swagger 注解
- 统一返回 `ApiResponse<T>` 结构
- 审计日志使用 `AuditLogRequestUtils`

### 14.2 数据权限注意事项
- 所有查询方法都需要集成 `@DataScope`
- Mapper XML 必须包含 `/*DATA_SCOPE*/` 占位符
- 测试时需验证不同数据权限角色的返回结果

### 14.3 事务管理
- 写操作必须标注 `@Transactional(rollbackFor = Exception.class)`
- 读操作默认不需要事务
- 避免大事务（审计日志记录应在事务外或异步）

### 14.4 性能考虑
- 列表查询必须分页
- 避免 N+1 查询（使用 JOIN 或批量查询）
- 唯一性检测使用 `EXISTS` 而非 `COUNT`
