# 账号管理真联调清单

## 1. 当前结论

- 本轮窗口化编辑方案已经落地了前端编辑弹窗、账号操作禁用逻辑，以及后端受保护账号校验链路。
- `AccountPage.tsx` 当前已能联动以下后端接口：
  - `GET /admin/api/v1/internal-users`
  - `GET /admin/api/v1/internal-users/{userId}`
  - `GET /admin/api/v1/internal-users/campus-options`
  - `PUT /admin/api/v1/internal-users/{userId}`
  - `PUT /admin/api/v1/internal-users/{userId}/status`
  - `PUT /admin/api/v1/internal-users/{userId}/reset-password`
- 后端已补齐：
  - 列表/详情返回 `systemAccount`、`currentUser`
  - 统一目标账号校验 `InternalUserOperationGuardService`
  - 修改/状态切换/重置密码三条写链路接入受保护账号与本人限制
  - `SYSTEM_ADMIN` 受保护角色配置与测试数据
- 当前已完成一轮格式统一、错误文案拆分、字段 nullability 收口、角色语义配置化，以及 `RoleProperties` 回退行为测试。
- 当前仍待收口的重点是：创建账号链路复用、真实环境联调验收，以及跨模块错误码口径继续统一。

## 2. 还建议完善的地方

### 2.1 前端仍建议补强

1. `[已完成]` `403` 错误文案已按场景拆分，不再统一翻译成“当前账号没有查看教务账号列表的权限”。
   - `AccountPage.tsx` 已按列表、详情、编辑加载、权限树、修改、状态切换、重置密码分别提示。
   - 页面侧 `permissionDenied` 也已改为基于稳定的 `403` 状态判断，而不是文案 contains。

2. `[已完成]` `AccountVisibilityPreview` 的控件风格已统一到 Ant Design。
   - 预览区域已切换为 `Select`、`Tree`、`Empty`、`Alert`。
   - 同页原生 `<select>`、自定义树形交互已移除。

3. `[已完成]` `systemAccount`、`currentUser` 的前端类型已收敛为必填 `boolean`。
   - `frontend/src/types/internalUser.ts` 已改为非空布尔。
   - 页面侧不再需要为这两个字段做多余的空值兜底。

4. `[未完成]` “创建账号”按钮后续如果启用，需要沿用同一套字段与限制。
   - 当前按钮还是禁用态。
   - 一旦恢复创建能力，前端表单字段、后端 DTO、角色/校区/数据范围约束要与编辑弹窗保持一致。

### 2.2 后端仍建议补强

1. `[已完成]` `SYSTEM_ADMIN` 与 `ADMIN` 的业务语义已做基础统一。
   - 受保护账号判断继续基于 `SYSTEM_ADMIN`。
   - “至少保留一个启用系统管理员账号”已走 `roleProperties.systemAdminRoleCode`，不再直接散落硬编码常量。
   - 当前约定为：
     - `SYSTEM_ADMIN`: 不允许在账号管理页被编辑/禁用/重置密码的保护角色
     - `ADMIN`: 普通管理员业务角色，用于权限与业务分工

2. `[已完成]` `RoleProperties` 的默认值已与 `application-common.yml` 对齐。
   - `preset-role-codes` 默认值已包含 `SYSTEM_ADMIN`
   - `protected-role-codes` 与 `system-admin-role-code` 已和公共配置口径一致
   - 已补充空配置 / 空白配置回退测试，保证默认值稳定生效

3. `[已完成]` 内部用户相关接口的关键错误文案和错误码已按操作场景做了一轮标准化。
   - 当前“用户不存在”“无权限操作该账号”“系统管理员账号不允许执行修改/修改状态/重置密码”“不能在账号管理中操作自己的账号”已经具备基础能力。
   - 新增统一文案包括：`状态值无效`、`数据范围类型无效`。
   - 当前内部用户相关接口已稳定区分参数错误 `400` 与权限错误 `403`，页面侧不需要再依赖脆弱的 message 判断。

4. `[已完成]` 可选校区接口权限边界已先行固定。
   - `/internal-users/campus-options` 现已支持 `admin:user:update` 或 `admin:user:create`。
   - 这样创建账号链路后续复用时不需要再额外切接口权限。
