# Backend 单体架构迁移到 Backend-Cloud 微服务架构

**版本**: v1.0
**创建日期**: 2026-04-29
**状态**: 规划中

---

## 1. 迁移概述

### 1.1 当前状态

| 项目 | 说明 |
|------|------|
| `backend/` | 单体应用，227 个 Java 文件 |
| `backend-cloud/` | 微服务架构骨架，已创建基础目录结构 |

### 1.2 迁移原则

1. **先迁移公共模块**：common 模块被所有服务依赖
2. **按服务逐个迁移**：auth → admin → 其他服务
3. **保持包结构一致**：迁移时保持子目录结构不变
4. **共享数据库**：所有服务共享同一个数据库，只是代码拆分

### 1.3 迁移顺序

```
Step 1: 公共模块 (chordsked-common-*)
    ↓
Step 2: 认证服务 (chordsked-auth)
    ↓
Step 3: 教务服务 (chordsked-admin)
    ↓
Step 4: 网关服务 (chordsked-gateway)
    ↓
Step 5: 其他服务 (teacher, student, notification)
```

## 10. 注意事项

### 10.1 包名调整

迁移后包名从 `com.chordsked.backend` 变为：
- `com.chordsked.common.*` (公共模块)
- `com.chordsked.auth` (认证服务)
- `com.chordsked.admin` (教务服务)
- `com.chordsked.student` (学员服务)
- `com.chordsked.notification` (通知服务)

### 10.2 依赖注入调整

原代码中的 `@Resource(name = "beanName")` 需要确保 Bean 名称在新服务中一致。

### 10.3 跨服务调用

迁移后，原本的方法调用需要改为 Feign 调用：

```java
// 迁移前 (单体应用)
@Resource
private InternalUserService internalUserService;

// 迁移后 (微服务)
@Resource
private AdminClient adminClient;  // Feign 客户端
```

### 10.4 数据库访问

所有服务共享同一个数据库，MyBatis Mapper XML 放在各服务的 resources/mapper 目录下。

### 10.5 配置管理

建议使用 Nacos Config 统一管理各服务配置。
