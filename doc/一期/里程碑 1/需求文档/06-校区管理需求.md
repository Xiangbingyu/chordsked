# 06-校区管理需求

**优先级**: P0  
**涉及端**: 后端、教务端

---

## 1. 功能概述

实现系统校区管理，支持校区的配置。数据权限基于用户与校区的绑定关系进行配置。

**设计说明**: 
- 校区是独立的经营单位
- 教务端账号可绑定多个校区（多对多关系，使用 `sys_user_campus` 表）
- 教师账号仅属于一个校区（一对一关系，在 `sys_teacher_user` 表中直接存储 `campus_id`）
- 学员用户仅属于一个校区（一对一关系，在 `sys_student_user` 表中直接存储 `campus_id`）
- 数据权限在用户级配置（仅适用于教务端账号）

**适用范围**:
- ✅ 教务端 - 校区管理配置入口
- ❌ 教师端 - 仅查看所属校区
- ❌ 学员端 - 仅查看所属校区

**以便** 扩展业务

**验收标准**:
- 可设置校区名称、地址、联系方式
- 可设置校区负责人

### 2.3 校区编辑

**作为** 系统管理员  
**我希望** 编辑校区信息  
**以便** 更新校区资料

**验收标准**:
- 可修改校区名称、地址、联系方式
- 可调整校区负责人
- 可设置校区状态（启用/停用）

### 2.4 用户校区绑定

**作为** 系统管理员  
**我希望** 为用户绑定校区  
**以便** 配置用户的数据权限范围

**验收标准**:
- 教务端账号可绑定多个校区（使用 `sys_user_campus` 表）
- 教师账号仅绑定一个校区（在 `sys_teacher_user` 表中直接存储 `campus_id`）
- 学员用户仅绑定一个校区（在 `sys_student_user` 表中直接存储 `campus_id`）
- 绑定后用户可访问并修改绑定校区的数据

## 3. 功能详情

### 3.1 校区列表

**功能描述**:
- 列表展示所有校区
- 支持分页
- 支持搜索和筛选

**查询条件**:
- 关键词（校区名称）
- 状态（启用/停用）

**列表字段**:
- 校区 ID
- 校区名称
- 地址
- 联系电话
- 负责人
- 用户数量
- 状态
- 创建时间

### 3.2 校区创建

**功能描述**:
- 创建新校区
- 设置校区基本信息

**输入信息**:
- 校区名称（唯一）
- 校区地址
- 联系电话
- 校区负责人
- 备注

**业务规则**:
- 校区名称必须唯一
- 联系电话格式验证

### 3.3 校区编辑

**功能描述**:
- 修改校区信息
- 调整校区负责人

**可修改信息**:
- 校区名称
- 校区地址
- 联系电话
- 校区负责人
- 状态
- 备注

**业务规则**:
- 校区名称修改后需验证唯一性

### 3.4 校区删除

**功能描述**:
- 删除不再使用的校区

**业务规则**:
- 有用户关联时不可删除
- 删除操作需二次确认

### 3.5 数据权限配置

**功能描述**:
- 在用户管理页面配置用户的数据权限范围
- 数据权限决定用户可访问并修改的数据范围

**数据权限范围**:

| 范围类型 | 说明 | 适用角色 |
|---------|------|---------|
| 全公司 | 可访问全系统所有数据 | 系统管理员、总部运营 |
| 本部门及下级部门 | 可访问本部门及下级部门的数据 | 部门负责人（二期） |
| 本人 | 仅访问本人相关数据 | 教师、普通员工 |

**校区绑定与数据权限的关系**:

| 用户类型 | 校区绑定 | 数据权限 |
|---------|---------|---------|
| 教务端账号 | 可绑定多个校区 | 根据数据权限范围 + 绑定校区决定 |
| 教师账号 | 仅绑定一个校区 | 固定为"本人"（仅查看已分配学员/本人课程） |
| 学员用户 | 仅绑定一个校区 | 仅访问本人数据 |

**示例**:
- 场景 1：系统管理员绑定多个校区 → 数据权限"全公司" → 可访问全系统数据
- 场景 2：教务运营绑定 3 个校区 → 数据权限"全公司" → 可访问这 3 个校区的数据
- 场景 3：教师属于 1 个校区 → 数据权限固定为"本人" → 仅查看已分配学员/本人课程

### 3.6 用户 - 校区关联

**功能描述**:
- 将用户关联到校区
- 教务端账号可关联多个校区（使用 `sys_user_campus` 表）
- 教师账号和学员用户仅关联一个校区（在各自用户表中直接存储 `campus_id`）

**关联信息**:
- 用户 ID
- 校区 ID
- 是否主校区（仅教务端账号用）

**业务规则**:
- 教务端账号可绑定多个校区（多对多，使用 `sys_user_campus` 表）
- 教师账号仅绑定一个校区（一对一，在 `sys_teacher_user` 表中直接存储 `campus_id`）
- 学员用户仅绑定一个校区（一对一，在 `sys_student_user` 表中直接存储 `campus_id`）
- 数据权限默认基于绑定校区

## 4. 数据要求

### 4.1 校区表 (sys_campus)

| 字段 | 类型 | 长度 | 必填 | 默认 | 约束 | 说明 |
|-----|------|------|-----|------|------|------|
| id | BIGINT | - | 是 | - | 主键 | 校区 ID |
| name | VARCHAR | 100 | 是 | - | 唯一 | 校区名称 |
| address | VARCHAR | 200 | 否 | - | - | 校区地址 |
| phone | VARCHAR | 20 | 否 | - | - | 联系电话 |
| leader_id | BIGINT | - | 否 | - | 外键 | 负责人 ID |
| leader_name | VARCHAR | 50 | 否 | - | - | 负责人姓名 |
| sort | INT | - | 是 | 0 | - | 排序号 |
| status | TINYINT | 1 | 是 | 1 | - | 状态（0 停用/1 启用） |
| remark | VARCHAR | 200 | 否 | - | - | 备注 |
| created_at | DATETIME | - | 是 | - | - | 创建时间 |
| updated_at | DATETIME | - | 是 | - | - | 更新时间 |

### 4.2 用户 - 校区关联表 (sys_user_campus)

| 字段 | 类型 | 长度 | 必填 | 默认 | 约束 | 说明 |
|-----|------|------|-----|------|------|------|
| id | BIGINT | - | 是 | - | 主键 | 关联 ID |
| user_id | BIGINT | - | 是 | - | 索引 | 用户 ID |
| campus_id | BIGINT | - | 是 | - | 索引 | 校区 ID |
| is_primary | TINYINT | 1 | 是 | 0 | - | 是否主校区（1 是/0 否） |
| created_at | DATETIME | - | 是 | - | - | 创建时间 |

> **设计说明**: 
> - 仅教务端用户可有多条记录（多对多）
> - 教师账号在 `sys_teacher_user` 表中直接存储 `campus_id`（一对一）
> - 学员用户在 `sys_student_user` 表中直接存储 `campus_id`（一对一）
> - 联合唯一约束：(user_id, campus_id)

## 7. 安全要求

1. **权限缓存**: 校区变更时应清除相关用户的数据权限缓存
2. **操作审计**: 校区创建、编辑、删除操作必须记录日志
3. **默认权限**: 用户默认拥有所绑定校区的数据权限
