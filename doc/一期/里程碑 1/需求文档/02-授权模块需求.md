# 02-授权模块需求

**优先级**: P0  
**涉及端**: 后端、教务端、教师端

---

## 1. 功能概述

实现基于角色的权限控制和数据权限隔离，确保用户只能访问授权的资源。

**适用范围**:
- ✅ 教务端（PC Web）- 需要角色权限控制
- ✅ 教师端（PC Web + 小程序）- 不需要角色权限配置，拥有所有页面权限，但数据权限受限
- ❌ 学员端（小程序）- 不需要权限控制，学员拥有所有页面操作权限

**设计原则**:
- **三套独立账号体系**：教务端、教师端、学员端完全独立
- **角色不关联校区**：角色仅定义功能权限，不绑定校区
- **数据权限在用户级配置**：通过用户与校区的绑定关系实现数据隔离
- **教师端简化设计**：教师拥有所有页面权限，数据自动过滤为本人相关
- **角色仅适用于教务端**：教师账号不需要角色配置，数据权限固定为"本人"

---

## 2. 用户故事

### 2.1 接口权限控制

**作为** 系统管理员  
**我希望** 配置不同角色的接口访问权限  
**以便** 控制用户可操作的功能范围

**验收标准**:
- 无权限用户访问受限接口返回无权限提示
- 权限配置修改后立即生效
- 支持页面按钮级权限控制

### 2.2 数据权限隔离（校区）

**作为** 系统管理员  
**我希望** 配置用户可访问的校区范围  
**以便** 控制用户数据访问范围

**验收标准**:
- 用户查询数据时仅返回权限范围内的数据
- 数据权限修改后立即生效

### 2.3 数据权限隔离（学员分配）

**作为** 教师  
**我希望** 只能查看已分配给我的学员  
**以便** 保护学员隐私和数据安全

**验收标准**:
- 教师查询学员列表时仅返回已分配学员
- 教师无法查看未分配学员的详细信息

## 3. 功能详情

### 3.1 权限拦截

**功能描述**:
- 用户访问接口时进行权限校验
- 无权限时返回统一错误提示

**业务规则**:
- 所有接口默认需要权限校验
- 公开接口（如登录）除外
- 权限不足时返回 403 状态码

### 3.2 数据权限隔离

**功能描述**:
- 根据用户配置的数据范围自动过滤数据
- 不同用户看到不同的数据范围

**数据权限范围类型**:

| 范围类型 | 说明 | 适用场景 |
|---------|------|---------|
| 全公司 | 可访问全系统所有数据 | 系统管理员、总部运营 |
| 本部门及下级部门 | 可访问本部门及下级部门的数据 | 部门负责人 |
| 本人 | 仅访问本人相关数据 | 教师、普通员工 |

**数据权限含义**:
- 数据权限范围内的数据 **可以查看并修改**
- 数据权限范围外的数据 **不可见**

**教师数据权限说明**:
- 教师拥有所有页面操作权限
- 数据查询时自动注入过滤条件（已分配学员、本人课程等）
- 无需通过角色权限配置

### 3.3 无权限处理

**功能描述**:
- 统一处理无权限访问
- 返回友好提示信息

**业务规则**:
- 返回统一错误码和提示
- 记录访问拒绝日志

## 4. 角色权限矩阵

### 4.1 系统管理员

拥有系统全部权限，可访问所有功能和数据（数据权限：全公司）。

### 4.2 教务运营

| 功能模块 | 权限 | 数据权限 |
|---------|------|---------|
| 用户管理 | 查看、编辑（不可删除） | 全公司 |
| 角色管理 | 查看（不可配置） | - |
| 订单管理 | 全部权限 | 全公司 |
| 学员管理 | 查看、编辑 | 全公司 |
| 教师管理 | 查看、编辑 | 全公司 |
| 审计日志 | 查看、详情（导出需单独授权） | 全公司 |

### 4.3 教师

**设计说明**: 教师端不需要角色权限配置，拥有所有页面操作权限，但数据查询自动过滤为本人相关数据。

| 功能模块 | 页面权限 | 数据权限 |
|---------|---------|---------|
| 学员管理 | ✅ 所有页面 | 仅查看已分配学员 |
| 个人课表 | ✅ 所有页面 | 仅查看本人课表 |
| 上课签到 | ✅ 所有页面 | 仅查看本人课程 |
| 课后反馈 | ✅ 所有页面 | 仅操作本人课程 |
| 作业管理 | ✅ 所有页面 | 仅查看已分配学员作业 |
| 个人 KPI | ✅ 所有页面 | 仅查看本人数据 |

### 4.4 学员/家长

**不需要权限控制**，学员端所有功能均可使用。

## 5. 权限配置管理

### 5.1 配置入口

**统一由教务端进行配置**:
- 角色管理页面 - 配置功能权限
- 用户管理页面 - 配置数据权限（校区绑定）

### 5.2 角色管理

**功能**:
- 创建/编辑/删除角色
- 为角色分配功能权限
- **不配置数据权限**（数据权限在用户级配置）

**业务规则**:
- 系统预置角色不可删除
- 角色有用户关联时不可删除

### 5.3 权限点管理

**权限类型**:
- 菜单权限：控制页面访问
- 按钮权限：控制页面内操作

**配置方式**:
- 树形结构展示权限点
- 勾选方式分配权限

### 5.4 数据权限配置

**配置层级**: **仅用户级配置**（角色不配置数据权限）

**配置方式**:
- 在用户管理页面配置用户的数据权限范围
- 数据权限范围：全公司 / 本部门及下级部门 / 本人

**业务规则**:
- 数据权限修改后立即生效
- 数据权限决定用户可访问并修改的数据范围

## 6. 数据要求

### 6.1 角色表 (sys_role)

| 字段 | 类型 | 长度 | 必填 | 约束 | 说明 |
|-----|------|------|-----|------|------|
| id | BIGINT | - | 是 | 主键 | 角色 ID |
| code | VARCHAR | 50 | 是 | 唯一 | 角色代码（如 ADMIN） |
| name | VARCHAR | 50 | 是 | - | 角色名称 |
| description | VARCHAR | 200 | 否 | - | 角色描述 |
| status | TINYINT | 1 | 是 | 默认 1 | 状态（0 禁用/1 启用） |
| created_at | DATETIME | - | 是 | - | 创建时间 |
| updated_at | DATETIME | - | 是 | - | 更新时间 |

> **设计说明**: 角色表**不包含** `data_scope` 和 `campus_id` 字段，数据权限在用户级配置。

### 6.2 权限表 (sys_permission)

| 字段 | 类型 | 长度 | 必填 | 约束 | 说明 |
|-----|------|------|-----|------|------|
| id | BIGINT | - | 是 | 主键 | 权限 ID |
| code | VARCHAR | 100 | 是 | 唯一 | 权限代码（如 user:read） |
| name | VARCHAR | 50 | 是 | - | 权限名称 |
| type | TINYINT | 1 | 是 | - | 类型（1 菜单/2 按钮） |
| parent_id | BIGINT | - | 否 | - | 父级权限 ID |
| path | VARCHAR | 200 | 否 | - | 前端路由路径 |
| sort | INT | - | 是 | 默认 0 | 排序号 |
| status | TINYINT | 1 | 是 | 默认 1 | 状态（0 禁用/1 启用） |
| created_at | DATETIME | - | 是 | - | 创建时间 |

### 6.3 用户 - 角色关联表 (sys_user_role)

| 字段 | 类型 | 长度 | 必填 | 约束 | 说明 |
|-----|------|------|-----|------|------|
| id | BIGINT | - | 是 | 主键 | 关联 ID |
| user_id | BIGINT | - | 是 | 索引 | 用户 ID |
| role_id | BIGINT | - | 是 | 索引 | 角色 ID |

### 6.4 角色 - 权限关联表 (sys_role_permission)

| 字段 | 类型 | 长度 | 必填 | 约束 | 说明 |
|-----|------|------|-----|------|------|
| id | BIGINT | - | 是 | 主键 | 关联 ID |
| role_id | BIGINT | - | 是 | 索引 | 角色 ID |
| permission_id | BIGINT | - | 是 | 索引 | 权限 ID |

### 6.5 用户 - 校区关联表 (sys_user_campus)

| 字段 | 类型 | 长度 | 必填 | 约束 | 说明 |
|-----|------|------|-----|------|------|
| id | BIGINT | - | 是 | 主键 | 关联 ID |
| user_id | BIGINT | - | 是 | 索引 | 用户 ID（教务端账号） |
| campus_id | BIGINT | - | 是 | 索引 | 校区 ID |
| is_primary | TINYINT | 1 | 是 | 默认 0 | 是否主校区（1 是/0 否） |

> **设计说明**: 
> - 仅用于教务端账号的多校区绑定（多对多关系）
> - 教师账号在 `sys_teacher_user` 表中直接存储 `campus_id`（一对一）
> - 学员用户在 `sys_student_user` 表中直接存储 `campus_id`（一对一）

### 6.6 账号体系说明

| 账号类型 | 使用表 | 登录方式 | 角色 | 数据权限 |
|---------|-------|---------|------|---------|
| 教务端账号 | `sys_internal_user` | 账号密码 | 需要（ADMIN/OPERATOR） | 可配置（全公司/本部门及下级部门/本人） |
| 教师端账号 | `sys_teacher_user` | 账号密码 | 不需要 | 固定为"本人" |
| 学员用户 | `sys_student_user` | 手机号 + 验证码 | 不需要 | 固定为"本人" |

> **设计说明**: 
> - 三套账号体系完全独立
> - 教师账号默认拥有教师端权限，无需额外配置
> - 学员用户无密码字段，仅使用验证码登录

## 7. 异常处理

| 异常场景 | 提示信息 |
|---------|---------|
| 无权访问该资源 | 您无权访问该资源，请联系管理员 |
| 数据权限不足 | 您无权查看该数据 |
| 角色已被禁用 | 您的角色已被禁用，请联系管理员 |

---

## 8. 安全要求

1. **权限缓存**: 用户权限应缓存，避免频繁查询
2. **权限实时生效**: 权限配置修改后应立即生效
3. **最小权限原则**: 默认拒绝所有，仅开放明确授权的权限
4. **审计日志**: 权限校验失败应记录日志
