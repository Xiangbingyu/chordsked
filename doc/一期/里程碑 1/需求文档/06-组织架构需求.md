# 06-组织架构需求

**优先级**: P0  
**涉及端**: 后端、教务端

---

## 1. 功能概述

实现系统组织架构管理，支持校区、部门等组织单元的配置，数据权限可基于组织架构进行配置。

**适用范围**:
- ✅ 教务端 - 组织架构配置入口
- ❌ 教师端 - 仅查看所属组织
- ❌ 学员端 - 仅查看所属组织

---

## 2. 用户故事

### 2.1 组织架构查看

**作为** 系统管理员  
**我希望** 查看系统组织架构  
**以便** 了解组织结构

**验收标准**:
- 树形结构展示组织架构
- 显示组织名称、类型、状态
- 显示组织下用户数量

### 2.2 组织架构创建

**作为** 系统管理员  
**我希望** 创建新的组织节点  
**以便** 建立组织结构

**验收标准**:
- 可创建校区、部门等组织类型
- 可设置上级组织
- 可设置组织负责人

### 2.3 组织架构编辑

**作为** 系统管理员  
**我希望** 编辑组织信息  
**以便** 更新组织资料

**验收标准**:
- 可修改组织名称、类型
- 可调整上级组织
- 可设置组织状态（启用/禁用）

### 2.4 数据权限配置

**作为** 系统管理员  
**我希望** 基于组织架构配置数据权限  
**以便** 控制用户数据访问范围

**验收标准**:
- 可为角色配置组织范围权限
- 可为用户单独配置组织范围权限
- 用户默认拥有本组织及下级组织数据权限

## 3. 功能详情

### 3.1 组织架构树

**功能描述**:
- 树形结构展示组织架构
- 支持展开/折叠
- 显示组织基本信息

**组织类型**:
- **校区 (CAMPUS)**: 独立经营单位（如：总部校区、XX 分校）
- **部门 (DEPT)**: 职能部门（如：教务部、教学部）
- **小组 (GROUP)**: 更小粒度的组织单元（如：吉他教研组、销售一组）

**组织层级说明**:
```
校区 (CAMPUS)     ← 第一级（根节点）
├── 部门 (DEPT)   ← 第二级
│   └── 小组 (GROUP) ← 第三级
```

**设计说明**: 校区与组织统一为同一实体，通过类型字段区分，不单独建表。

**树节点信息**:
- 组织 ID
- 组织名称
- 组织类型
- 负责人
- 用户数量
- 状态

### 3.2 组织创建

**功能描述**:
- 创建新的组织节点
- 设置组织基本信息

**输入信息**:
- 组织名称
- 组织类型（校区/部门/小组）
- 上级组织
- 组织负责人
- 排序号
- 备注

**业务规则**:
- 组织名称在同一上级下必须唯一
- 校区不能设为部门的下级
- 根节点只能是校区类型

### 3.3 组织编辑

**功能描述**:
- 修改组织信息
- 调整组织层级

**可修改信息**:
- 组织名称
- 组织类型
- 上级组织
- 组织负责人
- 状态
- 排序号
- 备注

**业务规则**:
- 不能将组织设为自己下级的下级（循环引用）
- 组织有下级时不能改为非层级类型

### 3.4 组织删除

**功能描述**:
- 删除不再使用的组织节点

**业务规则**:
- 有下级组织时不可删除
- 有用户关联时不可删除
- 删除操作需二次确认

### 3.5 数据权限配置

**功能描述**:
- 基于组织架构配置数据权限
- 支持角色级和用户级配置

**配置方式**:

**角色级配置**:
- 为角色配置默认可访问的组织范围
- 可选：全部组织、指定组织（支持多选）、本组织及下级、仅本组织

**用户级配置**:
- 为用户单独配置可访问的组织范围
- 用户级配置优先于角色级配置
- 默认为用户所属组织及下级组织

**数据权限范围**:

| 范围类型 | 说明 | 配置方式 |
|---------|------|---------|
| 全部组织 | 可访问全系统所有组织数据 | 无需选择 |
| 指定组织 | 仅访问指定的组织数据（**支持多选**） | 从组织树中选择多个组织 |
| 本组织及下级 | 访问本人所属组织及下级组织数据 | 自动计算 |
| 仅本组织 | 仅访问本人所属组织数据 | 自动获取用户主组织 |
| 个人数据 | 仅访问本人数据 | 无需选择 |

**多选组织示例**:
- 场景：区域经理管理 3 个校区
- 配置：选择"指定组织"，勾选"总部校区"、"XX 分校"、"YY 分校"
- 效果：该用户可查看这 3 个校区及其下级部门的所有数据

### 3.6 用户组织关联

**功能描述**:
- 将用户关联到组织
- 一个用户可属于多个组织

**关联信息**:
- 用户 ID
- 组织 ID
- 是否主组织
- 关联时间

**业务规则**:
- 一个用户必须有一个主组织
- 用户可关联多个组织
- 用户数据权限默认基于主组织

## 4. 数据要求

### 4.1 组织表 (sys_organization)

**设计说明**: 校区与组织统一为此表，通过 type 字段区分类型。

| 字段 | 类型 | 长度 | 必填 | 默认 | 约束 | 说明 |
|-----|------|------|-----|------|------|------|
| id | BIGINT | - | 是 | - | 主键 | 组织 ID |
| name | VARCHAR | 100 | 是 | - | 同级唯一 | 组织名称 |
| type | VARCHAR | 20 | 是 | - | - | 类型（CAMPUS/DEPT/GROUP） |
| parent_id | BIGINT | - | 否 | - | 外键 | 上级组织 ID |
| level | INT | - | 是 | - | - | 组织层级（1=校区，2=部门，3=小组） |
| leader_id | BIGINT | - | 否 | - | 外键 | 负责人 ID |
| leader_name | VARCHAR | 50 | 否 | - | - | 负责人姓名 |
| address | VARCHAR | 200 | 否 | - | - | 校区地址（仅校区类型使用） |
| phone | VARCHAR | 20 | 否 | - | - | 联系电话（仅校区类型使用） |
| sort | INT | - | 是 | 0 | - | 排序号 |
| status | TINYINT | 1 | 是 | 1 | - | 状态（0 禁用/1 启用） |
| remark | VARCHAR | 200 | 否 | - | - | 备注 |
| created_at | DATETIME | - | 是 | - | - | 创建时间 |
| updated_at | DATETIME | - | 是 | - | - | 更新时间 |

### 4.2 用户 - 组织关联表 (sys_user_org)

| 字段 | 类型 | 长度 | 必填 | 默认 | 约束 | 说明 |
|-----|------|------|-----|------|------|------|
| id | BIGINT | - | 是 | - | 主键 | 关联 ID |
| user_id | BIGINT | - | 是 | - | 索引 | 用户 ID |
| org_id | BIGINT | - | 是 | - | 索引 | 组织 ID |
| is_primary | TINYINT | 1 | 是 | 0 | - | 是否主组织（1 是/0 否） |
| created_at | DATETIME | - | 是 | - | - | 关联时间 |

### 4.3 数据权限配置表 (sys_data_scope)

| 字段 | 类型 | 长度 | 必填 | 默认 | 约束 | 说明 |
|-----|------|------|-----|------|------|------|
| id | BIGINT | - | 是 | - | 主键 | 配置 ID |
| target_type | VARCHAR | 20 | 是 | - | - | 目标类型（ROLE/USER） |
| target_id | BIGINT | - | 是 | - | 索引 | 角色 ID 或用户 ID |
| scope_type | VARCHAR | 20 | 是 | - | - | 范围类型（ALL/SPECIFIED/CURRENT_AND_SUB/CURRENT/SELF） |
| org_ids | TEXT | - | 否 | - | - | 指定组织 ID 列表（JSON 数组） |
| created_at | DATETIME | - | 是 | - | - | 创建时间 |
| updated_at | DATETIME | - | 是 | - | - | 更新时间 |

## 5. 异常处理

| 异常场景 | 提示信息 |
|---------|---------|
| 组织名称已存在 | 组织名称已存在，请更换 |
| 组织不存在 | 组织不存在 |
| 组织有下级 | 组织有下级，无法删除 |
| 组织有用户关联 | 组织有用户关联，请先移除用户 |
| 循环引用 | 不能将组织设为自己下级的下级 |

## 6. 前端页面要求

### 6.1 组织架构管理页面

**功能**:
- 树形结构展示组织架构
- 支持展开/折叠
- 右键菜单：新增、编辑、删除
- 显示组织基本信息

### 6.2 组织创建/编辑表单

**字段**:
- 组织名称
- 组织类型（下拉选择：校区/部门/小组）
- 上级组织（树形选择器）
- 组织负责人（用户选择器）
- 排序号
- 状态（启用/禁用）
- 备注（多行文本）

### 6.3 数据权限配置页面

**功能**:
- 选择配置对象（角色/用户）
- 选择数据权限范围
- 指定组织（多选）
- 保存配置

---

## 7. 安全要求

1. **权限缓存**: 组织架构变更时应清除相关用户的数据权限缓存
2. **操作审计**: 组织创建、编辑、删除操作必须记录日志
3. **默认权限**: 用户默认拥有本组织及下级组织数据权限
4. **权限优先**: 用户级配置优先于角色级配置
