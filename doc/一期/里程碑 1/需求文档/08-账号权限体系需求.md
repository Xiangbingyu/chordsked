# 里程碑 1：账号权限体系

**版本**: v1.0  
**更新日期**: 2026-03-24  
**状态**: 规划中

---

## 1. 概述

本里程碑定义 ChordSked 吉他教育课程管理系统的账号权限体系，确保各角色用户能够访问其职责范围内的功能和数据，同时保障系统安全性。

---

## 2. 用户角色定义

### 2.1 角色清单

| 角色代码 | 角色名称 | 说明 | 使用端 |
|---------|---------|------|-------|
| `ADMIN` | 系统管理员 | 拥有系统全部权限，负责系统配置、权限管理 | 教务端 |
| `OPERATOR` | 教务运营 | 负责日常运营操作（订单核销、排课、学员管理） | 教务端 |
| `TEACHER` | 教师 | 负责授课、作业批改、学员反馈 | 教师端 + 小程序 |
| `STUDENT` | 学员 | 预约课程、查看课表、提交作业 | 小程序 |
| `PARENT` | 家长 | 代学员预约课程、查看学习记录、评价老师 | 小程序 |
| `CAMPUS_ADMIN` | 校区负责人 | 管理单校区数据、查看 KPI 统计 | 教务端（二期） |
| `HQ_ADMIN` | 总部管理员 | 查看多校区汇总数据（二期） | 教务端（二期） |

## 3. 用户管理需求

### 3.1 内部用户管理

内部用户指在后台管理系统中使用的员工账号，包括 ADMIN、OPERATOR、TEACHER、CAMPUS_ADMIN。

#### 3.1.1 账号创建

| 角色 | 创建权限 | 必填信息 | 说明 |
|-----|---------|---------|------|
| ADMIN | 仅 ADMIN 可创建 | 用户名、姓名、手机号、角色 | 系统管理员 |
| OPERATOR | ADMIN 可创建 | 用户名、姓名、手机号、角色 | 教务运营 |
| TEACHER | ADMIN、OPERATOR 可创建 | 用户名、姓名、手机号、角色 | 教师 |
| CAMPUS_ADMIN | ADMIN 可创建 | 用户名、姓名、手机号、角色 | 校区负责人（二期） |

**账号字段**:
| 字段 | 必填 | 说明 |
|-----|------|------|
| 用户名 | ✅ | 登录用户名（唯一） |
| 姓名 | ✅ | 真实姓名 |
| 手机号 | ✅ | 手机号（唯一） |
| 角色 | ✅ | ADMIN/OPERATOR/TEACHER/CAMPUS_ADMIN |
| 邮箱 | ❌ | - |
| 绑定校区 | ⚠️ | TEACHER 和 CAMPUS_ADMIN 必填，决定数据权限范围 |

**初始密码策略**:
- 系统自动生成随机初始密码（12 位，包含大小写字母 + 数字 + 特殊字符）
- 创建时显示一次，需管理员自行记录并交付给用户
- 首次登录强制修改密码
- 初始密码 7 天内有效，逾期需管理员重置

#### 3.1.2 账号编辑

| 字段 | 可编辑 | 说明 |
|-----|-------|------|
| 姓名 | ✅ | 所有角色可编辑 |
| 手机号 | ✅ | 需验证唯一性 |
| 邮箱 | ✅ | - |
| 头像 | ✅ | - |
| 角色 | ⚠️ | 仅 ADMIN 可修改他人角色 |
| 校区绑定 | ⚠️ | ADMIN 可修改所有，OPERATOR 仅可修改教师 |
| 账号状态 | ⚠️ | ADMIN 可修改所有，OPERATOR 仅可禁用教师 |

#### 3.1.3 账号删除

| 角色 | 删除规则 |
|-----|---------|
| ADMIN | 不可删除最后一个 ADMIN 账号 |
| OPERATOR | 有进行中的操作时不可删除 |
| TEACHER | 有进行中的课程/学员时不可删除 |
| CAMPUS_ADMIN | 该校区无其他管理员时可删除 |

**删除策略**: 默认采用软删除，设置 `deletedAt` 时间戳，30 天内可恢复。

#### 3.1.4 账号状态

| 状态 | 说明 | 触发条件 | 恢复方式 |
|-----|------|---------|---------|
| ACTIVE | 正常 | 默认状态 | - |
| INACTIVE | 禁用 | 管理员手动禁用 | 管理员启用 |
| LOCKED | 锁定 | 登录失败 5 次 | 30 分钟后自动解锁/管理员解锁 |
| PENDING | 待激活 | 账号创建后 | 用户首次登录修改密码 |

#### 3.1.5 批量操作

- **批量导入**: 支持 Excel/CSV 文件批量导入内部账号
- **批量导出**: 支持导出用户列表为 Excel/CSV 文件
- **批量禁用/启用**: 选中多个账号批量操作

#### 3.1.6 登录与安全

| 认证方式 | 说明 | 适用角色 |
|---------|------|---------|
| 账号密码 | 用户名 + 密码 | 所有内部用户 |
| 手机号 + 验证码 | 手机号 + 短信验证码 | 所有内部用户（可选） |
| MFA | 密码 + Google Authenticator | ADMIN、OPERATOR（可选，二期） |

**密码策略**:
- 最小长度：8 位
- 复杂度：包含大小写字母 + 数字 + 特殊字符（至少 3 类）
- 加密方式：BCrypt（迭代次数 12）
- 登录失败限制：5 次失败后锁定 30 分钟

### 3.2 外部用户管理

外部用户指通过小程序/移动端访问的用户，当前版本**仅支持学员账号新建**。

#### 3.2.1 学员账号创建方式

#### 3.2.2 学员账号字段

| 字段 | 必填 | 说明 |
|-----|------|------|
| 姓名 | ✅ | 学员姓名 |
| 手机号 | ✅ | 手机号（唯一，登录账号） |
| 校区 | ✅ | 选择所属校区 |
| 性别 | ❌ | 男/女 |
| 出生日期 | ❌ | - |
| 分配教师 | ❌ | 可选，后续可调整 |
| 备注 | ❌ | 内部备注信息 |

#### 3.2.3 家长账号（二期）

|-----|------|

#### 3.2.4 外部用户登录

| 认证方式 | 说明 |
|---------|------|
| 手机号 + 验证码 | 手机号 + 短信验证码 |
| 微信一键登录 | 微信小程序授权登录（二期） |

## 5. 认证与授权机制

### 5.1 认证方式

| 用户类型 | 认证方式 | Token 类型 | 有效期 |
|---------|---------|-----------|-------|
| 后台用户 | 账号密码 + 可选 MFA | JWT Access + Refresh | Access: 2h, Refresh: 7d |
| 小程序用户 | 手机号 + 短信验证码 | JWT Access + Refresh | Access: 2h, Refresh: 30d |
| 教师（移动端） | 手机号 + 短信验证码 | JWT Access + Refresh | Access: 2h, Refresh: 30d |

### 5.2 权限校验流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   客户端     │ ──▶ │  API 网关    │ ──▶ │  业务服务    │
│  (携带 Token)│     │ (Token 验证) │     │ (权限校验)   │
└─────────────┘     └─────────────┘     └─────────────┘
                           │                     │
                           ▼                     ▼
                    ┌─────────────┐     ┌─────────────┐
                    │ JWT 解析     │     │ RBAC 校验    │
                    │ - 用户 ID    │     │ - 角色权限   │
                    │ - 角色列表   │     │ - 功能权限   │
                    │ - 权限列表   │     │ - 资源访问   │
                    └─────────────┘     └─────────────┘
                                              │
                                              ▼
                                       ┌─────────────┐
                                       │ 数据范围过滤 │
                                       │ - 账号绑定校区│
                                       │ - 已分配学员 │
                                       └─────────────┘
```

### 5.3 数据权限说明

> **设计原则**: 角色仅定义功能权限（能做什么操作），不关联校区、不配置数据权限。
>
> **数据权限实现**: 通过账号与校区的绑定关系实现数据隔离，在账号管理模块统一配置。

| 角色 | 功能权限说明 | 数据范围决定因素 |
|-----|------------|-----------------|
| ADMIN | 全部功能权限 | 默认为全系统数据 |
| OPERATOR | 运营相关功能权限 | 默认为全系统数据 |
| CAMPUS_ADMIN | 校区管理功能权限 | 由账号绑定的校区决定 |
| TEACHER | 教学相关功能权限 | 由账号绑定的校区 + 已分配学员决定 |
| STUDENT/PARENT | 个人/学员功能权限 | 仅本人/绑定学员信息 |

## 6. 安全策略

### 6.1 密码安全

- **后台账号**: 初始密码强制首次登录修改
- **密码复杂度**: 最少 8 位，包含大小写字母 + 数字
- **密码存储**: BCrypt 加密（迭代次数 12）
- **登录失败限制**: 5 次失败后锁定 30 分钟

### 6.2 Token 安全

- **JWT Secret**: 环境变量配置，禁止默认值
- **Token 刷新**: Refresh Token 一次性使用
- **Token 撤销**: 支持主动登出、账号禁用时撤销

### 6.3 接口安全

- **API 认证**: 所有 API 需携带有效 Token
- **公开接口**: 仅登录、注册、Swagger 文档公开
- **请求签名**: 敏感操作（删除、权限修改）需额外签名

### 6.4 审计日志

| 操作类型 | 记录内容 | 保留期限 |
|---------|---------|---------|
| 登录/登出 | 用户 ID、IP、时间、结果 | 180 天 |
| 权限修改 | 操作人、目标用户、变更内容 | 365 天 |
| 数据导出 | 操作人、导出范围、数据量 | 365 天 |

### 9.1 设计原则说明

> **角色简化原则**: 角色仅定义功能权限，不关联校区、不配置数据权限。
>
> - **角色** = 能做什么操作（功能权限）
> - **账号绑定** = 能访问哪些数据（数据权限）
>
> 这种设计使得角色配置更简单、复用性更高，数据权限通过账号管理灵活配置。
