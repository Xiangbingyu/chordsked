## 🔄 流程闭环

### 闭环 1：用户登录认证流程

```
用户输入账号密码 → 后端验证密码 → 生成 JWT+Refresh Token → 返回前端存储
       ▲                                                        │
       │                                                        ▼
       │    登录成功跳转首页 ← 权限加载 ← Token 解析获取用户信息
       └────────────────────────────────────────────────────────┘
```

### 闭环 2：权限校验流程

```
前端发起 API 请求 → 网关拦截验证 Token → 解析角色获取权限 → 权限匹配决定是否放行
                                              │
                    ✅ 通过                    │  ❌ 拒绝
                    ▼                         ▼
               调用业务处理逻辑            返回 403 拒绝访问
```

### 闭环 3：数据权限隔离流程

```
用户查询请求 → 识别用户数据权限范围 → 动态添加 SQL 过滤条件 → 执行查询返回结果
```

**数据权限范围**：
- **全公司**：可访问全系统所有数据
- **本部门及下级部门**：可访问本部门及下级部门的数据
- **本人**：仅访问本人相关数据

**教师数据权限**：
```
教师查询 → 自动注入过滤条件（已分配学员/本人课程） → 返回本人相关数据
```

### 闭环 4：学员账号创建流程

```
教务后台手动创建学员账号 → 设置所属校区 → 发送短信通知 → 学员手机号登录
```

> **注**：学员账号仅支持后台手动创建，不支持登录时自动创建。

## ⚠️ 重要说明

### 核心设计原则

1. **三套独立账号体系**
   - 教务端账号：管理员、教务运营，使用 `sys_internal_user` 表，账号密码登录
   - 教师端账号：教师，使用 `sys_teacher_user` 表，账号密码登录
   - 学员用户：学员，使用 `sys_student_user` 表，手机号 + 验证码登录
   - 三套账号体系完全独立，无关联

2. **角色不关联校区**
   - 角色仅定义功能权限（能做什么操作）
   - 数据权限在用户级配置（能访问哪些数据）
   - **仅适用于教务端账号**，教师账号不需要角色配置

3. **用户与校区关系**
   - 教务端账号：多对多（一个用户可绑定多个校区，使用 `sys_user_campus` 表）
   - 教师账号：一对一（一个教师仅属于一个校区，在 `sys_teacher_user` 表中直接存储 `campus_id`）
   - 学员用户：一对一（一个学员仅属于一个校区，在 `sys_student_user` 表中直接存储 `campus_id`）

4. **教师端权限设计**
   - 教师端不需要角色权限配置
   - 教师拥有所有页面操作权限
   - 数据查询时自动注入过滤条件（已分配学员/本人课程）
   - 教师数据权限固定为"本人"，无需配置

5. **数据权限范围**（仅适用于教务端账号）
   - **全公司**：可访问并修改全系统数据
   - **本部门及下级部门**：可访问并修改本部门及下级部门数据
   - **本人**：仅访问并修改本人相关数据

6. **用户表结构**
   - 教务端账号表：`sys_internal_user`（含角色关联）
   - 教师端账号表：`sys_teacher_user`（含 `campus_id` 字段，无角色关联）
   - 学员用户表：`sys_student_user`（含 `campus_id` 字段，无密码字段）
   - 用户 - 校区关联表：`sys_user_campus`（仅用于教务端账号的多校区绑定）

7. **教师账号字段**
   - 教师姓名、工号、联系方式
   - 授课类型（一对一/小班/大班/全部）
   - 教师等级（初级/中级/高级/资深）
   - 所属校区（一对一）
   - 状态（在职/离职/停用）
   - 教学资历、擅长曲目

8. **学员账号创建**
   - 仅支持后台手动创建
   - 不支持登录时自动创建
   - 不支持小程序自主注册（二期）
   - 学员仅使用手机号 + 验证码登录，无密码

9. **密码复杂度要求**
   - 8 位以上
   - 包含大小写字母 + 数字 + 特殊字符
   - 至少满足 3 类
   - 仅适用于教务端账号和教师端账号，学员用户无密码
