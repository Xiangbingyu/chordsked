# 02-授权与数据隔离设计

---

## 1. 责任链模式/拦截器模式 (Interceptor Pattern) - 授权模块

**场景**：API 请求需要经过 Token 校验、角色权限校验。
**设计**：采用轻量级安全框架（如 Sa-Token 或基于 Spring Security 深度定制），统一处理鉴权流程。
- `JwtAuthInterceptor`：负责解析 Token，识别用户身份。
- `PermissionInterceptor`：针对教务端用户，拦截 API 并比对角色拥有的权限点（RBAC）。

---

## 2. 授权验证执行流程

当一个请求到达系统时，安全框架的拦截流程如下：

```mermaid
sequenceDiagram
    participant Client as 客户端
    participant SecurityFilter as JwtAuthenticationFilter
    participant MultiAccountUserDetailsService as 多账号路由服务
    participant InternalAccountProvider as 教务端账号服务
    participant SpringSecurity as SecurityContextHolder
    participant Controller as 业务接口 (@PreAuthorize)

    Client->>SecurityFilter: 1. 发起请求 (携带 JWT Token)
    SecurityFilter->>SecurityFilter: 2. 解析 JWT, 获取 UserType 和 UserId
    
    SecurityFilter->>MultiAccountUserDetailsService: 3. loadUserByTokenContext(UserType, UserId)
    
    alt UserType == 'ADMIN'
        MultiAccountUserDetailsService->>InternalAccountProvider: 4a. 获取教务用户及权限
        InternalAccountProvider-->>MultiAccountUserDetailsService: 5a. 返回包含[user:add, role:edit]等权限的UserDetails
    else UserType == 'TEACHER'
        MultiAccountUserDetailsService->>TeacherAccountProvider: 4b. 获取教师信息
        TeacherAccountProvider-->>MultiAccountUserDetailsService: 5b. 返回包含[ROLE_TEACHER]的UserDetails
    end
    
    MultiAccountUserDetailsService-->>SecurityFilter: 6. 返回 UserDetails
    SecurityFilter->>SpringSecurity: 7. 将 UserDetails 存入 SecurityContext
    
    SpringSecurity->>Controller: 8. 请求到达目标接口
    Controller->>Controller: 9. 执行 @PreAuthorize("hasAuthority('user:add')")
    
    alt 权限匹配
        Controller-->>Client: 10a. 返回业务数据
    else 权限不足或角色不匹配
        Controller-->>Client: 10b. 返回 403 Forbidden
    end
```

### 2.1 对接优势
- **隔离性好**：安全框架层不关心底层的三张表结构，只面向抽象的 `AccountProvider` 接口。
- **配置简化**：教师端和学员端的 API 只需配置 `@PreAuthorize("hasRole('TEACHER')")` 即可放行所有相关接口，而教务端则可精确到 `@PreAuthorize("hasAuthority('role:create')")`。

## 3. 策略模式 + 代理模式 - 数据权限隔离组件化

**场景**：不同角色的数据权限范围不同，且未来可能扩展更多维度（如基于部门、区域甚至特定属性）。
**设计**：将数据权限隔离 `DataScope` 抽取为独立的通用组件。利用 MyBatis 的 Interceptor（代理模式）拦截 SQL，并结合**策略模式**（Strategy Pattern）处理不同的权限范围过滤逻辑，实现与业务代码的解耦。

### 3.1 核心组件类图设计

```mermaid
classDiagram
    class Interceptor {
        <<interface>>
        +intercept(Invocation invocation) Object
    }
    
    class DataScopeInterceptor {
        -DataScopeStrategyFactory strategyFactory
        -SqlParserCache sqlCache
        +intercept(Invocation invocation) Object
        -buildDataScopeSql(String originalSql, UserContext user) String
    }
    
    class DataScopeStrategyFactory {
        -Map~Integer, DataScopeStrategy~ strategies
        +getStrategy(Integer dataScopeType) DataScopeStrategy
    }
    
    class DataScopeStrategy {
        <<interface>>
        +getCondition(UserContext user, String tableAlias) String
    }
    
    class AllDataScopeStrategy {
        +getCondition(UserContext user, String tableAlias) String
    }
    
    class DeptDataScopeStrategy {
        +getCondition(UserContext user, String tableAlias) String
    }
    
    class SelfDataScopeStrategy {
        +getCondition(UserContext user, String tableAlias) String
    }
    
    class CampusDataScopeStrategy {
        +getCondition(UserContext user, String tableAlias) String
    }
    
    class AbacDataScopeStrategy {
        +getCondition(UserContext user, String tableAlias) String
    }

    Interceptor <|.. DataScopeInterceptor
    DataScopeInterceptor --> DataScopeStrategyFactory
    DataScopeStrategyFactory --> DataScopeStrategy
    DataScopeStrategy <|.. AllDataScopeStrategy
    DataScopeStrategy <|.. DeptDataScopeStrategy
    DataScopeStrategy <|.. SelfDataScopeStrategy
    DataScopeStrategy <|.. CampusDataScopeStrategy
    DataScopeStrategy <|.. AbacDataScopeStrategy
```

### 3.2 核心组件说明
1. **统一拦截器 `DataScopeInterceptor`**：
   - 仅对标注了 `@DataScope` 注解的 Mapper 方法进行拦截。
   - 解析注解信息，获取当前用户的 `data_scope_type`，将其分发给对应的策略实现类。
2. **策略接口与实现 (`DataScopeStrategy`)**：
   - 定义 `DataScopeStrategy` 接口，包含 `getCondition(User user, String tableAlias)` 方法。
   - 实现不同的策略类：
     - `AllDataScopeStrategy` (全公司)：返回空条件。
     - `DeptDataScopeStrategy` (本部门及下级)：返回 `AND dept_id IN (...)`。
     - `SelfDataScopeStrategy` (本人)：返回 `AND create_by = 当前登录者ID`。
     - `CampusDataScopeStrategy` (指定校区)：返回 `AND campus_id IN (...)`。
3. **预留 ABAC 扩展点 (Attribute-Based Access Control)**：
   - `DataScope` 组件在设计时，上下文上下文不仅传递用户 ID 和角色，还包含环境上下文（如当前时间、请求 IP）及用户属性集合。
   - 未来若需基于属性控制权限（如：只允许在特定网络环境下查看高价值学员数据），只需新增一个 `AbacDataScopeStrategy` 策略类，解析这些属性并生成对应的 SQL 条件即可，无需重构现有架构。

**性能优化设计**：
- **SQL AST 解析缓存**：针对复杂 SQL，使用 JSqlParser 等 AST 工具解析时性能损耗较大。系统应对“原始 SQL -> 注入点 AST 结构”的映射关系进行**本地缓存 (如 Caffeine/ConcurrentHashMap)**，同一条 SQL 在二次执行时直接复用解析结果进行条件拼接。

### 3.3 权限校验与数据隔离执行流程

```mermaid
sequenceDiagram
    actor Client as 客户端
    participant Interceptor as 权限拦截器 (WebMvc)
    participant Controller as 业务控制器
    participant Service as 业务逻辑层
    participant DataScope as 数据权限拦截器 (MyBatis)
    participant DB as 数据库

    Client->>Interceptor: 1. 发起 API 请求 (Header 带 Token)
    Interceptor->>Interceptor: 2. 验证 JWT 签名及有效期
    Interceptor->>Interceptor: 3. 解析 UserType 和 UserId
    
    alt 是教务端请求
        Interceptor->>Interceptor: 4a. 提取 API 所需权限点 (@PreAuthorize)
        Interceptor->>Redis: 5a. 查询用户拥有的角色及权限
        Redis-->>Interceptor: 6a. 返回权限列表
        Interceptor->>Interceptor: 7a. 权限比对 (通过/拒绝)
    else 是教师/学员请求
        Interceptor->>Interceptor: 4b. 验证 Token 有效性即可放行
    end
    
    Interceptor->>Controller: 8. 放行请求，将 UserContext 存入 ThreadLocal
    Controller->>Service: 9. 调用业务方法
    Service->>DataScope: 10. 执行数据库查询
    
    DataScope->>DataScope: 11. 从 ThreadLocal 获取 UserContext
    alt 教务端用户
        DataScope->>DataScope: 12a. 根据 data_scope_type 动态拼接 SQL (如 AND campus_id IN ...)
    else 教师/学员用户
        DataScope->>DataScope: 12b. 动态拼接 SQL: AND user_id = 当前ID
    end
    
    DataScope->>DB: 13. 执行改写后的 SQL
    DB-->>DataScope: 14. 返回过滤后的数据
    DataScope-->>Service: 15. 返回数据
    Service-->>Controller: 16. 返回 DTO
    Controller-->>Client: 17. 返回响应结果
```
