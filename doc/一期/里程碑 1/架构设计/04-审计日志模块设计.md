# 04-审计日志模块设计

为满足系统安全性与合规性要求，避免将海量的常规系统请求日志与高价值的核心业务操作日志混为一谈，本模块设计**将操作日志与审计日志进行严格分离**。

## 1. 核心概念分离

1. **系统操作日志 (Operation Log)**：
   - **定位**：记录系统中大部分用户的日常读写操作轨迹（如查询列表、点击菜单）。
   - **实现**：通过 AOP 全局拦截或网关过滤器自动记录。
   - **存储**：写入 ElasticSearch 或轻量级时序数据库，仅供开发排查问题，生命周期短（如 30 天）。
2. **核心审计日志 (Audit Log)**：
   - **定位**：记录系统中具有**高风险、高敏感、高业务价值**的操作（如修改权限、分配角色、重置密码、导出学员数据、大额订单审核等）。
   - **实现**：基于 `@AuditLog` 注解精确拦截，或业务代码中显式调用 Service。
   - **存储**：写入关系型数据库（如 MySQL），提供前端查询界面，生命周期长（如 6 个月以上），满足合规与法务要求。

---

## 2. 审计日志记录核心信息
所有带有 `@AuditLog` 注解的接口操作，将通过 AOP 异步记录到 `sys_audit_log` 表中，不阻塞主业务流程。
记录内容包括：
- **操作人信息**：操作人 ID、姓名、所属端（教务/教师/学员）。
- **操作内容**：模块名称、业务动作（新增/修改/删除/导出等）、请求参数、响应结果。
- **环境信息**：操作时间、IP 地址、User-Agent。

## 2. 审计日志表结构设计

```sql
CREATE TABLE sys_audit_log (
    id BIGINT PRIMARY KEY,
    user_id BIGINT COMMENT '操作人ID',
    user_name VARCHAR(50) COMMENT '操作人姓名',
    user_type VARCHAR(20) COMMENT '账号类型(ADMIN/TEACHER/STUDENT)',
    module_name VARCHAR(50) COMMENT '业务模块',
    action_type VARCHAR(20) COMMENT '操作类型',
    request_ip VARCHAR(50) COMMENT 'IP地址',
    request_url VARCHAR(255) COMMENT '请求URL',
    request_params TEXT COMMENT '请求参数',
    response_result TEXT COMMENT '响应结果',
    status TINYINT COMMENT '操作状态(1:成功 0:失败)',
    error_msg TEXT COMMENT '错误信息',
    created_at DATETIME COMMENT '操作时间',
    
    INDEX idx_user_id (user_id),
    INDEX idx_module_action (module_name, action_type),
    INDEX idx_created_at (created_at)
);
```

## 4. 手动记录日志接口设计

除了基于 `@AuditLog` 注解的自动拦截外，系统提供 `AuditLogService` 接口，允许在复杂业务代码中手动记录重要的业务轨迹。

```java
public interface AuditLogService {
    
    /**
     * 手动记录审计日志
     * 
     * @param moduleName  模块名称 (如: "排课管理")
     * @param actionType  操作类型 (如: "MANUAL_CANCEL_COURSE")
     * @param requestParams 核心业务参数 (可传 JSON 字符串或核心业务 ID)
     * @param result      操作结果 (成功/失败描述)
     * @param status      状态 (1:成功 0:失败)
     */
    void recordLog(String moduleName, String actionType, String requestParams, String result, Integer status);
    
    /**
     * 手动记录成功日志 (简易版)
     */
    void recordSuccess(String moduleName, String actionType, String requestParams);
    
    /**
     * 手动记录失败日志 (简易版)
     */
    void recordError(String moduleName, String actionType, String requestParams, String errorMsg);
}
```

**使用场景示例**：当一段复杂的业务逻辑（如批量排课或导入数据）中包含多步操作，且某一步出错需要记录具体的失败原因，而非整个接口报错时，可在 `catch` 块中调用 `recordError` 记录。

## 5. 日志管理机制
- **查询接口**：教务端提供分页查询接口，支持按模块、操作人、操作时间段、状态进行筛选。
- **日志保留期限**：为了避免单表数据量过大，日志数据默认保留 **6 个月**。可通过定时任务定期将过期日志归档到冷数据表或直接清理。

---

## 6. 安全性与扩展性说明

1. **Token 安全**：采用双 Token 机制（Access Token 2小时，Refresh Token 7天），降低 Token 泄露风险。登录失败 5 次锁定 30 分钟，防止暴力破解。
2. **动态数据权限**：基于 MyBatis Interceptor 实现的 `DataScope` 机制，业务代码（Service/Mapper）**零侵入**。
3. **审计日志解耦**：基于 AOP 异步处理，保证业务接口响应速度。
